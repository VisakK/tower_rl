5. **The teacher stays intact and runnable.** `Executor`, the graph JSONs and the bundles are the parity reference and
   the fallback. Never delete them or change their behaviour. Every new hook defaults to off, so the teacher's
   rehearsals stay bit-identical.
6. **Operating rules** (learned the hard way, also in the project memory):
   - Run one GPU job at a time; check `nvidia-smi` first. The machine once hard-reset under load.
   - Stay headless. Wrap GPU jobs in `scripts/run_logged.sh <log> ...`.
   - Stop jobs with `kill -9 <python pid>`. Never use `pkill -f` or `kill $(pgrep -f ...)`: both match the calling
     shell.
   - Call `torch.set_num_threads(1)` in every CPU script.
   - Never pass `--kit_args=--/persistent/...`.
   - End Kit scripts with `os._exit(0)`.
   - Source the venv before `nohup`.
   - Editing a running bash queue script does not change it: kill and relaunch.
   - CPU rehearsals are deterministic only for the same code, bundle, seeds and process history: batch b depends on
     batches 0..b-1. So A/B comparisons run the same seeds, the same `--num_envs` and the same batch order, in
     separate processes.
7. **Commits and backups.** The user commits; never commit or push unless asked. Before the first code change, take a
   backup: `results/backups/code_<date>_pre_student.tgz`, as session 3 did.

### 1.3 Challenge facts that constrain the student (live docs, 2026-10-21)

- **Observation:**
  - four RGB images, 480 × 640, consumed as delivered. The static ones arrive turned by 180°, like the dataset JPEGs.
  - `joint_positions` [2, 7] float32 (left, then back) and `gripper_widths_m` [2];
  - `instruction` and `task_variant`;
  - `step_index` (control actions executed so far) and `sim_time_s`.

  There are no block poses.
- **Action:** little-endian float32 `[H, 16]`, with 1 ≤ H ≤ `max_chunk_actions` (16).
  - Columns: left j1–j7, left gripper width, back j1–j7, back gripper width.
  - Absolute radians and metres, inside `action_lower` / `action_upper`.
  - `dt_s` = `action_dt_s` (0.1 at 10 Hz).
- **Protocol** `tower-infer-v1`:
  - msgpack frames; NumPy arrays as extension type 42; dtypes `|u1`, `<f4`, `<f8`;
  - server metadata within 10 s of connecting;
  - `reset` → `reset_ack`, and `infer` → `infer_result`, echoing `protocol`, `session_id`, `trial_id`, `request_id`
    and `policy_id`;
  - seed fields (`tower-seed-stream-v1`). Details are in Step 11.
- **Concurrency:** one evaluation runs up to **8 episodes at once** against the server. Sessions are independent: state
  is kept per `session_id` and cleared on reset. `inference_timeout_s` and `episode_wall_timeout_s` come from
  `track.json`, which needs a sign-in.
- **Budget:** 210 s of simulated time per episode. The 10 Hz track is the only validated one. Ten variants × 10
  episodes (1 nominal + 9 robustness cases).
- **Rules.** Submission Rules v1.3 (2026-10-15), as quoted in `Teacher_build_session.MD` §2; the docs pages did not
  show them on 2026-10-21.
  - Required: a learned policy or a model-driven agent.
  - Permitted: supporting controllers, inverse kinematics and safety filters; deterministic learned policies; action
    chunks; observation-driven code generated by an agent.
  - Prohibited: prerecorded replay, fixed scripted solutions, unauthorized simulator information, scoring exploits and
    human intervention. A "nominal model wrapper does not qualify".
  - The organizers' README adds that task-specific hard-coding from test layouts disqualifies a run, and that top
    teams share their code for verification.
- **Obsolete files.** `policy_server/serve_policy.py` and `docs/protocol.md` in this repository describe the obsolete
  `tower-openpi-v1`. Use the docs' starter kit instead (Step 11).

## 2. The method

### 2.1 Architecture

```
observation: 4 RGB + q [2,7] + widths [2] + task_variant + sim_time_s
  │
  ▼
perception (kp_v2 + multi-view fit; unchanged) ─────────► per block: pose, confidence
  ▲ focus = target block of the running option                    │
task spec (variant → goals + option templates) ───────────────────┤   runtime memory (own options and their outcomes)
                                                                   ▼
tokens: blocks, goals, arms, global  ──►  SWITCHER: set transformer, ~0.5 M parameters, runs on the CPU
                                            heads: option ∈ {acquire, deliver, push_off, insert, push_home, park, idle},
                                                   goal pointer, arm; progress P(satisfied) per goal; value (Step 12)
  ▲ called when an option ends, and every 2 s while idle             │
  │                                                                 ▼
OPTION RUNTIME: option → node specs from the task spec → existing node classes
                (planned approach transit → learned contact skill → mechanical end)
  │
  ▼
IK + sag-compensated controller → [H,16] chunks (16 rows in transit, 1 row per call in contact, as now)
```

### 2.2 Options

| Option | Families | Nodes (from the task spec) | Arguments | Ends when |
|---|---|---|---|---|
| `acquire` | transfer, insertion | transit `pregrasp` + `grasp_lift` (Task 5: planned, distilled in Step 9c) | goal k, arm | the grasp node returns ok, failed or timeout |
| `deliver` | transfer | transit `preplace` (held) + `place_release` | goal k, arm | the place verdict |
| `push_off` | pushdown | transit `prepush` + `push` | goal k, arm | the push node: departed, structure, shoved or timeout |
| `insert` | insertion | transit `preinsert` (held) + `insert` | goal k, arm | the insert verdict |
| `push_home` | insertion | transit `prepushin` + `push_in` | goal k, arm | the push-in verdict |
| `park` | all | `park` | arm | the arm is at home |
| `idle` | all | hold the current command | – | 2 s of sim time; then the switcher decides again |

The runtime also applies mechanical rules. They are safety filters, not decisions:
- An option that does not deliver or insert the block an arm holds first opens that arm's gripper. The executor's skip
  does the same.
- `_clearance_park` stays: before a transit into a tower that the other arm occupies, the other arm is parked as an
  inserted node.
- **Action masks:**
  - `deliver` and `insert` only for the goal whose block that arm holds;
  - only the option types of the variant's family;
  - goal index < K;
  - `idle` is always allowed.
- Every row is clipped to the joint limits and the track's action bounds. A non-finite value turns the chunk into a
  hold chunk.

### 2.3 The switcher

- **Inputs** (the exact list is in Appendix B):
  - block tokens: pose relative to the pads, yaw as cos/sin 2ψ, tilt, confidence level, role, which arm holds it,
    motion, and family-specific geometry (offset to its goal or slot, travel along its push);
  - goal tokens: type, prescribed order, the demos' arm, the bound block's features, the goal geometry, the history
    (attempts per arm, last option and status, failure category, arm switch tried), and whether each arm can reach
    the pre-grasp (IK);
  - arm tokens: pinch pose, width, gripper command, at home, last option;
  - a global token: variant, family, time left.
- **Only deployable inputs:** estimator outputs (the noise model's during training), joint angles, widths, the
  runtime's own history, kinematics and the task spec. Never `State.privileged`.
- **Network:** a pre-LN transformer encoder with 3 layers, d = 128 and 4 heads, over [global, 2 arm, ≤ 16 block,
  ≤ 9 goal] tokens with padding masks. Each token type has its own input projection plus a type embedding. Heads:
  - option: 7 logits from the global token;
  - goal pointer: a query from the global token + the option embedding, dotted with the goal tokens;
  - arm: 2 logits from the global token + the chosen goal;
  - progress: a sigmoid per goal token;
  - value: a scalar, used in Step 12.

  The probability factorises as p(option) · p(goal | option) · p(arm | option, goal). Decoding is a deterministic
  argmax with the masks applied.
- **When it runs:**
  - at the start of the episode;
  - whenever an option ends, inside the same `act` call (as the executor advances nodes);
  - every 2 s of `idle`.

  It takes under 1 ms per call, and the number of inference calls does not change.

### 2.4 The progress head ("is the job done, what remains")

For each goal, the head outputs P(satisfied now). It is trained on the local evaluator's instantaneous truth
conditions:
- **transfer:** the P condition of `OperationTracker`: released, within 5 mm in xy, 10 mm in z and 5° in yaw, static,
  with the lower layers in place;
- **pushdown:** departed from the tower and static (`PushTracker`);
- **insertion:** in the slot within tolerance, released, static, with the structure intact.

Task progress is the mean over goals. The runtime uses the head only for logging, monitoring and the server's status
line. Decisions come from the decision heads, which share its representation.

### 2.5 The oracle (expert), and why it is needed

The executor's decisions depend on its program counter. It therefore cannot label the states a student visits after
deviating from the graph. The oracle restates the graph's semantics as a function of the scene plus the runtime
memory, in two modes.

**Graph mode** has exact executor semantics: latched node verdicts, retries, skips, arm switches, parks before arm
switches, and the fell-off-the-table skip. It reads nothing privileged, so it is deployable. It has two uses:
- proving the option runtime correct, by bit-identical parity with the executor (Step 3);
- serving as the decision layer of the first official evaluation if the switcher is not ready.

**State mode** is the expert used for the training labels. It is graph mode with four changes:
- "Goal satisfied" comes from simulator truth (`State.privileged["ops"]`).
- A goal that truth says is satisfied is never reworked, even if its node verdict failed.
- A satisfied goal that is later disturbed is reopened if its block is accessible: transfer family only, top of the
  destination stack, at least 30 s left, at most once per goal.
- A re-grasp uses whichever arm can reach the pre-grasp, the prescribed arm first.

Because it reads truth, state mode is a training expert only. It must be at least as good as graph mode (Step 3 gate).

### 2.6 The training pipeline

1. **Data** comes from privileged CPU rehearsals. **EstimatorNoise** (Step 5) is applied to what the runtime sees, so
   the tokens look like estimator output. The truth stays in `privileged`, for the oracle's labels and the progress
   labels.
2. **Round 0:** the oracle (state mode) acts. Two mechanisms cover recovery states:
   - **failure injection** (DART-style): a random 15 % of options are perturbed so that they produce real drops,
     misplacements, knocks and shoves;
   - **ε-exploration:** at 10 % of decision points a random valid alternative is executed.
3. **Behaviour cloning:** train the switcher on every logged decision (the oracle's labels) plus the progress labels.
4. **DAgger:** the switcher acts, mixed with the oracle (β = 0.5 in round 1, β = 0 in round 2), and the oracle labels
   every decision. Aggregate the data and retrain. Two rounds.
5. **RL over options** (optional, Step 12): advantage-weighted regression on the evaluator's rewards, with exploration
   at branch points.
6. **Validation** in the camera loop with kp_v2 (Step 10).

### 2.7 Skills

- **9a, push.** Add a "target seen" input (and the number of calls since it was last seen). Retrain from v3 (left) and
  v1c (back) with the estimator's failure modes, from Step 5's fit: the target lost for 1–5 calls while it tips,
  coasted, then found again lying on its side. Policies with the new input no longer need the executor's hand-coded
  hold.
- **9b, grip.** A 42.5 mm hold command gives about 2.9 N per finger whether the evaluator limits finger effort to 3 N or
  to 22 N, because it never reaches the limit. That makes Tasks 1–3 insensitive to the open 3 N question. Test it
  first; fine-tune grasp and place with effort ∈ {3, 22} N only if needed.
- **9c, Task 5.** Distil the planned grasp, insert and push-in into networks on the CPU station scene: DART-style
  imitation of the planned controllers. GPU physics cannot do the 1–2 mm clearances. The planned controllers stay as
  the fallback.

### 2.8 Rules position (for the method description)

- **Learned:**
  - block keypoint detection (a CNN);
  - every task-level decision (the switcher);
  - progress estimation;
  - contact manipulation for every operation type: PPO actors, and distilled networks for Task 5.
- **Engineered:**
  - the multi-view geometric fit of the detections;
  - IK and gravity-sag compensation;
  - planned free-space transits;
  - option geometry from perceived anchors and training-layout offsets;
  - safety filters.
- **No LLM or agent at inference.** Agent-written code covers the offline tooling, the runtime, the oracle (used only as
  a training expert) and the supporting controllers.
- **Learning from a scripted expert** is how the organizers' own dataset, itself scripted-planner output, is meant to be
  used.
- **Still ask the organizers** (Appendix D).

     - `stages`: the family's ordered list of stages, each holding the graph's node specs:

       | Family | Stage | Nodes |
       |---|---|---|
       | transfer | `acquire` | `t{k}_to_pregrasp`, `t{k}_grasp` |
       | transfer | `deliver` | `t{k}_to_preplace`, `t{k}_place` |
       | pushdown | `push_off` | `p{k}_to_prepush`, `p{k}_push` |
       | insertion | `acquire` | `i{k}_to_pregrasp`, `i{k}_grasp` |
       | insertion | `insert` | `i{k}_to_preinsert`, `i{k}_insert` |
       | insertion | `push_home` | `i{k}_to_prepushin`, `i{k}_push_in` |

     - the geometry fields that tokens use: `dest_layer`, `goal_in_pad`, `goal_z`, `direction`, `side_blocks`,
       `layer`.
   - **`park_spec(arm, k, kind)`**: a park node spec, named exactly as the executor names them: `park_{arm}_{k}`,
     `park_{arm}_end`, `t{k}_alt_park_{arm}` and `auto_park_{arm}`, with the graph's timeouts.
   - **`option_nodes(decision)`**: deep copies of a stage's node specs with `arm` replaced. When the arm differs from the
     prescribed one, ids get the `_alt` suffix and `first_of_transfer` is set to false, as `_schedule_arm_switch` does.
2. **Validation.** Every non-park node of every graph belongs to exactly one (goal, stage). Stages follow the family
   order above. Parks appear only between transfers that switch arms, and at the end.

**Gate:** `pytest tests/test_student_spec.py`. All ten graphs, in the repo and in `teacher_t45_final`, round-trip:
concatenating the option node specs in prescribed order, with the parks reinserted where the graph has them, gives back
the graph's node list exactly, every field included.

### Step 2: the option runtime (Oct 22)

**Deliverables**
1. **`tower_rl/student/runtime.py`.**
   - **`StudentRun(EnvRun)`** reuses everything in `EnvRun`: controllers, grippers, attach / detach / refresh, rest
     estimates, `dest_goal`, `slot_pose`, `_clearance_park`, `_pregrasp_reachable` and `_expand`. It adds:
     - state: `self.spec` (`TaskSpec`), `self.decider` (oracle or switcher), `self.queue` (the node specs of the running
       option), `self.option` (the current `Decision`) and `self.memory` (`Memory`, below);
     - **`act(s)`**, with the same structure as `EnvRun.act`:
       - reset the controllers on the first call, then `observe(s)`;
       - loop over at most 64 node steps, applying the 30 Hz expansion to the same node classes, and stop at the first
         rows;
       - when no node runs and the queue is empty, call `decide(s)`, apply the mechanical rules (§2.2), fill the queue
         with `spec.option_nodes(decision)` (or a park, or idle) and continue in the same call;
     - **`_node_done(status, s)`**:
       - append `(t, node id, status, info)` to `events`, exactly as `EnvRun._advance` does;
       - an inserted park changes nothing else;
       - a failed node aborts the rest of its option;
       - clean up as the executor does: if the arm still holds the goal's block, keep the gripper closed; otherwise
         `grip.reset(closed=False)` and `detach`;
       - record the option's outcome in the memory;
     - **`idle`**: emit the hold row (`self.row()[None]`) and call `decide` again after 2 s of sim time.
   - **`Memory`** holds:
     - per goal:
       - `tries`: failed non-park options;
       - `attempts[arm]`: options started;
       - `last_option`, `last_status`;
       - `last_why`: a category mapped from the node's `info["why"]` and place errors (none, ok, dropped, unreachable,
         structure, shoved, misplaced, stalled, lost, timeout, other);
       - `alt`: none, queued or done;
       - `closed`: the oracle's bookkeeping only, never a token;
     - per arm: `last_option` and `moved_since_park`;
     - `option_log`: decision, t_start, t_end, status, info.
   - **`StudentExecutor`** implements the runner's `Policy` protocol:
     - `from_bundle(bundle, variant, device, rate_hz, decider)`, `reset` and `act`;
     - `episode_log(e)`, which returns the events;
     - `focus_block(e)`: the block id of the running option, or None for park and idle;
     - `node_info(e)`: skill and node id;
     - a `graph` attribute pointing at the spec's graph dict, so `--graph_set` keeps working.
2. **`Executor.focus_block(e)` and `Executor.node_info(e)`** with today's semantics. `CameraPerception` switches to them.
3. **Rehearsal flag.** `rehearse.py --student oracle_graph | oracle_state | <switcher.pt>` builds a `StudentExecutor`
   instead of an `Executor`. Output dirs get a `_student-<name>` suffix; the report and metrics are unchanged.
   `rehearse_many.py` passes the flag through.

**Gate:**

### Step 3: the oracle and parity (Oct 22–23)

**Deliverables**
1. **`tower_rl/student/oracle.py`**: `Oracle(mode)` with `decide(view) -> Decision(option, goal, arm)`. The `view`
   holds:
   - the state, plus the truth when present (`privileged["true_block_pos"]`, `privileged["ops"]`);
   - the memory and the spec;
   - the run's kinematic helpers (`_pregrasp_reachable`, the holding test).

   Graph mode has exact executor semantics:
   ```
   decide:
     if an arm-switch sequence is queued: return its next item
     k = the first goal, in prescribed order, that is not closed
     if k is None: park the last active arm if it moved since its park, else idle
     arm = goal k's prescribed arm
     if the other arm moved since its last park: return park(other)       # the graph's park before an arm switch
     stage = deliver / insert if this arm holds goal k's block, else the next stage of the family's stage machine
     return (stage, k, arm)
   on option end:
     ok   -> the stage advances; the last stage closes goal k
     fail -> park: ignore
             policy = the failed node's on_fail ("skip" for insert and push_in, else "retry")
             retry, but goal k's block has z < -0.02 (fell off the table) -> skip
             a deliver failed, near miss <= arm_switch_m, the own arm cannot reach the pre-grasp, the other arm can,
             and no arm switch yet -> queue [park(arm), acquire(k, other), deliver(k, other), park(other)];
                                      alt = queued
             tries[k] += 1; skip if the policy is skip or tries[k] > retries (2): close goal k
             else, if the arm still holds the block and the stage is a transport (deliver / insert): retry that stage
             else: restart from acquire (the runtime opens the gripper)
     arm-switch sequence: a failed non-park item drops the remaining non-park items;
                          when the queue empties, close goal k
   ```
   State mode adds the four changes of §2.5. It needs the truth (`privileged`), so it is a training expert only.

### Step 12: RL over options (optional, after G10; nights of Oct 27–28)

**Deliverables:** `tower_rl/student/awr.py` and `configs/student/awr.yaml`.
- **Reward** for decision i: r_i = ΔG_i + ΔP_i (latched successes during option i) − 0.5 · (blocks newly disturbed
  during option i) − 0.002 · duration_s. A terminal +5 · task_success. Return-to-go G_i, with γ = 1.
- **Value head:** trained by MSE on G_i.
- **Advantage:** A_i = G_i − V(s_i). Weights w_i = min(exp(A_i / β), 20), with β tuned so that about 30 % of the weight
  mass falls on the top 10 % of decisions.
- **Loss:** Σ w_i · CE(executed decision) + λ_bc · CE(oracle label), with λ_bc 0.5, plus the progress and value
  terms.
- **Data:** 2 rounds × 2,000 episodes, D1-heavy, injection at 0.1. Exploration ε = 0.2, only at branch points: after
  a failure, the choice of arm for a re-grasp, and reopen decisions. Same seed discipline.

**Gate G12:**

## 6. Invariants

- The switcher, the runtime and every skill read only deployable inputs. Truth is used only for labels, rewards, the
  state-mode oracle and the evaluator.
- `State` keeps one schema for simulator truth, the noise model and the estimator's output. `focus` comes from the
  runtime.
- Goals come from the perceived anchors plus training-layout offsets (the task spec). Nothing reads organizer
  descriptors or test layouts at execution time.
- Inference is deterministic given the observation stream: no LLM calls, no randomness.
- All tunables live in configs. Results go under `results/student/`, with config hashes. One BUILDLOG entry per session.
- The executor, the graphs and the teacher bundles stay runnable, with unchanged behaviour: they are the parity
  reference and the fallback.
- Training, rehearsal and the server use the same token code: one function and one feature version, recorded in the
  bundle.

## 7. Things that silently break the student

- A token that reads `privileged`, or truth leaking through `block_conf` = 1 in privileged runs. Train with
  `--est_noise`.
- A token or normalizer mismatch between training and deployment. Shards and the bundle carry the feature version;
  refuse to load on a mismatch.
- Train and eval seeds that overlap. Comparing runs with different `--num_envs` or batch order (CPU history).
- Parity broken by "harmless" changes to node classes. Every node change must keep G3a.
- Labels the student cannot infer: state mode deciding from truth about blocks the estimator has lost. Check label
  noise per feature in the offline evaluation.
- Confidence semantics: the estimator's 0.3 ("not seen") returns the previous pose, so the noise model must do the same.
- Quaternion half-turn twins. Tokens use cos/sin 2ψ. Skills need continuous quaternions; the estimator and
  `EstimatorNoise` keep them continuous.
- The camera model: `source="evaluator"` on the server, `"render"` in rehearsal and in ws_loop. Images are consumed as
  delivered.
- Observation flags that differ between a skill's training env and its node, like the push_in "closed" bug of
  session 3. Unit-test each retrained or distilled skill's observation function against its env.
- The 30 Hz expansion applied to new node types. The student is 10 Hz only.
- Action bounds: clip to `track.json`'s bounds, not only to the joint limits.
- The server:
  - mutable state shared between sessions;
  - a reset that does not clear the runtime and the estimator;
  - advertising `reconnect` without the full contract.
- GPU contention: a training job during a camera-loop run or an official evaluation.

## Appendix B: token features, v1

Every distance is in metres, multiplied as noted so that values stay near unit scale. The pad centres are the
layout's `pads.source.center` and `pads.destination.center`.

**Block token** (up to 16 blocks, in `block_ids` order; padding is masked):

| Feature | Dims | Definition |
|---|---|---|
| role | 6 | one-hot: source foundation, destination foundation, movable (Tasks 1–4), side, roof, insert |
| position | 6 | perceived centre relative to the source pad centre (3) and to the destination pad centre (3), ×10 |
| yaw | 2 | cos 2ψ, sin 2ψ (half-turn symmetric) |
| tilt | 1 | angle between the block's z axis and the world z axis (rad) |
| confidence | 4 | one-hot of the estimator's level: ≥ 1, 0.6, 0.3, 0 |
| seen | 1 | calls since the confidence was last ≥ 0.5, divided by 10 and clipped to 1 |
| held by | 3 | one-hot: none, left, back. An arm holds the block if its gripper command is closed, its width is in [0.044, 0.056] and the block centre is within 3 cm of its pinch |
| motion | 2 | displacement since the episode start (×10); speed over the last 1 s (m/s, ×10) |
| goal offset | 5 | for a block bound to a goal: block minus goal (dx, dy, dz ×100; cos and sin of 2Δψ); else zeros |
| push frame | 3 | Task 4 blocks: travel along and across the push direction since the start (×10), radial distance from the tower axis (×10); else zeros |
| slot frame | 3 | Task 5 inserts: along, across and vertical offset from the slot (×10); else zeros |
| bound | 1 | 1 if the block is bound to a goal |
| fallen | 1 | perceived z < 0, or confidence 0 for ≥ 20 calls |

**Goal token** (up to 9, in prescribed order):

| Feature | Dims | Definition |
|---|---|---|
| type | 3 | one-hot: place, push_off, insert |
| order | 10 | k / K, and one-hot of k (9) |
| prescribed arm | 2 | one-hot |
| bound block | 38 | a copy of the bound block's token features |
| goal geometry | 5 | goal position relative to the destination pad centre (×10); cos and sin of 2 × (goal yaw − pad yaw) |
| history | 28 | attempts per arm / 3 (2); tries / 3 (1); last option, one-hot (7); last status, one-hot: none, ok, failed, timeout (4); last failure category, one-hot (11); arm switch: none, queued, done (3) |
| reachability | 2 | the pre-grasp is reachable by the left / back arm (`_pregrasp_reachable`); zeros for goals without an acquire stage |

**Arm token** (2):

| Feature | Dims | Definition |
|---|---|---|
| arm id | 2 | one-hot |
| pinch position | 6 | relative to the source and destination pad centres (×10) |
| pinch orientation | 6 | rot6d |
| width | 1 | ×10 |
| gripper command closed | 1 | |
| holding | 1 | the executor's holding test |
| at home | 1 | max \|q − home\| < 0.05 rad |
| moved since park | 1 | |
| last option | 7 | one-hot |
| time since the last option ended | 1 | s / 10, clipped to 1 |

**Global token:** variant one-hot (10), family one-hot (3), (210 − t) / 210 (1), K / 9 (1), decisions so far / 50 (1).

| Array | Shape | Contents |
|---|---|---|
